# 📋 Вкладка настройки и просмотра параметров журналов событий Windows (Log Settings Tab)

Интерактивная панель управления и диагностики журналов событий Windows (`Security.evtx`, `System.evtx`, `Application.evtx`, `Sysmon` и др.).

---

## 🎯 Возможности вкладки

1. **Мониторинг параметров каналов:**
   - Текущий размер файла на диске (.evtx), максимальный разрешенный размер (Max Size), процент заполнения.
   - Количество сохраненных записей (Record Count) и диапазон Record ID (старейший..новейший).
   - Политика переполнения (FIFO-перезапись, Auto-Backup архивация, Retention удержание).

2. **Настройка конфигурации журналов:**
   - Изменение максимального размера журнала (пресеты 20MB, 64MB, 128MB, 256MB, 512MB, 1GB, 2GB, 4GB или произвольный в МБ).
   - Включение/отключение сбора событий в канал (`wevtutil sl /e:true|false`).
   - Настройка политик архивации и ротации.
   - Очистка журнала с автоматическим созданием резервной копии `.evtx`.

3. **Аудит безопасности и Телеметрия:**
   - Включение/отключение аудита командных строк процессов (`ProcessCreationIncludeCmdLine_Enabled` в реестре) для Event ID 4688.
   - Проверка прав доступа к Security Log (`SeSecurityPrivilege`).
   - Управление закладками (Bookmark) инкрементального сборщика в `telemetry.db` и сброс на конец журнала.
   - Ручной запуск инкрементального сбора телеметрии.

4. **Инспектор событий реального времени:**
   - Просмотр событий любых каналов и нормализованной базы `telemetry.db`.
   - Быстрые фильтры Event ID: `4688` (Создание процесса), `4624` (Вход), `4625` (Сбой входа), `1102` (Очистка журнала).
   - Детальный инспектор с отображением процесса, PID, родительского процесса, пользователя, командной строки и исходного XML.

## 🌐 API Эндпоинты

- `GET /api/v1/log-settings/channels` — получение параметров всех каналов.
- `GET /api/v1/log-settings/channel/{name}` — детальные параметры канала.
- `POST /api/v1/log-settings/channel/config` — изменение параметров канала.
- `POST /api/v1/log-settings/channel/clear` — очистка журнала.
- `GET /api/v1/log-settings/audit-status` — статус аудита CommandLine и закладки.
- `POST /api/v1/log-settings/audit-status/cmdline` — включение/выключение аудита CommandLine в реестре.
- `POST /api/v1/log-settings/collector/collect` — запуск инкрементального сбора.
- `POST /api/v1/log-settings/collector/reset-bookmark` — сброс закладки сборщика.
- `GET /api/v1/log-settings/events` — чтение и фильтрация событий.

## 🏗️ Архитектура модуля

Модуль декомпозирован на панели с соблюдением стандарта `<= 500` строк функционального кода (`GEMINI.md`):

```text
apps/windows/api/webgui/tab_log_settings/
├── index.html                  # Разметка 6 подразделов, сводные карточки и модальные окна
├── main.js                     # Главный оркестратор (153 строки), экспорт в window.initLogSettingsTab
├── README.md                   # Документация модуля на русском языке
├── common/
│   └── ui_utils.js             # Экранирование HTML, проверка активности вкладки
├── panel_domains/
│   └── panel.js                # Сводка 7 доменов ОС, иерархический каталог провайдеров
├── panel_channels/
│   └── panel.js                # Таблица каналов Event Log, модалки настройки лимитов и очистки
├── panel_security/
│   └── panel.js                # Аудит CommandLine (4688), права SeSecurityPrivilege, закладка Bookmark
├── panel_provenance/
│   └── panel.js                # Граф происхождения процессов (Provenance)
├── panel_lifecycle/
│   └── panel.js                # Хронология жизненного цикла ОС (Power / Boot / Crash Timeline)
└── panel_inspector/
    └── panel.js                # Инспектор событий, фильтрация по Event ID, детальное досье
```
