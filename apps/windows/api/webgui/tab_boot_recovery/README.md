## 📋 Описание

Консолидированная панель администрирования жизненного цикла загрузки, целостности системных файлов и интеллектуального управления точками восстановления Windows. 

Объединяет три функциональные панели в единый пользовательский интерфейс:
1. **Параметры загрузки и WinRE:** Управление записями Windows Boot Manager (BCD), таймаутом загрузчика, проверкой и включением среды восстановления WinRE (`reagentc.exe`).
2. **Проверка целостности SFC / DISM:** Анализ и очистка хранилища компонентов WinSxS, сканирование целостности системных файлов (`sfc /scannow`), обслуживание образа Windows (`DISM /ScanHealth`, `/RestoreHealth`).
3. **Умное восстановление (RestorePointAdvisor):** Интеллектуальный советник и контроллер точек восстановления Windows.

## 🧱 Архитектура модулей WebGUI
В соответствии со стандартами рефакторинга и лимитом строк (<= 500 строк) логика интерфейса разделена на изолированные панели:
- `panel_bcd_winre/panel.js` — модуль управления параметрами загрузчика BCD и среды восстановления WinRE.
- `panel_smart_restore/panel.js` — модуль оценки необходимости создания точек восстановления (RestorePointAdvisor), журнал состояний и ИИ-объяснение.
- `main.js` — координатор инициализации вкладки, регистрация поллера и переключение субвкладок.

## 🛡️ Панель «Умное восстановление» (RestorePointAdvisor)

Перед созданием контрольной точки Advisor проводит предварительный аудит состояния системы и отвечает на три ключевых вопроса:

1. **Есть ли смысл создавать точку?**
   - Анализ существенных изменений в 8 категориях: Драйверы (`DRIVERS`), Программы (`SOFTWARE`), Службы (`SERVICES`), Обновления Windows (`UPDATES`), Конфигурация загрузки (`BOOT_BCD`), Системные ветви реестра (`REGISTRY`), Критичные системные файлы ядра (`SYSTEM_FILES`). Пользовательские файлы (`USER_FILES`) исключаются.
2. **Не дублирует ли она предыдущую?**
   - Нормализованное вычисление SHA-256 отпечатков (*Fingerprints*) по каждой категории и композитного хеша системы. Если отпечатки идентичны предыдущему снимку, повторная точка не создается (вердикт `SKIP`).
3. **Достаточно ли данных и условий для восстановления?**
   - Проверка включения System Protection на системном диске C:, доступности службы VSS (Volume Shadow Copy) и наличия свободного дискового пространства (> 1 ГБ).

### Политика принятия решений
- `CREATE` — зафиксированы критические изменения конфигурации (драйверы, системные компоненты, обновления).
- `SKIP` — существенных изменений не произошло, состояние идентично предыдущей точке.
- `MONITOR` — незначительные изменения зафиксированы в журнале дельт, создание точки отложено.
- `CLARIFY` — недостаточно данных или сбой защитных механизмов (например, отключен VSS).

## 🗄️ Локальное хранилище журнала состояний (SQLite)

История снимков и дельт состояний сохраняется локально в SQLite по пути:
```
%ProgramData%\AI-Windows-Admin\apps\windows\telemetry\logs\state_journal.sqlite
```

Таблицы:
- `smart_restore_snapshots` — снимки состояний, категориальные хеши, решения и статус создания точек Windows.
- `smart_restore_deltas` — детальные дельты изменений (добавленные, удаленные и измененные объекты).

| Метод | URL | Описание |
|---|---|---|
| `GET` | `/api/boot-recovery/summary` | Сводка BCD и среды WinRE |

| `POST` | `/api/v1/windows-checkpoints/advisor/create-smart` | Умное создание точки восстановления |
| `GET` | `/api/v1/windows-checkpoints/advisor/journal` | Получение истории снимков состояний из SQLite |
| `POST` | `/api/v1/windows-checkpoints/advisor/explain` | Формирование объяснения логики решения |
